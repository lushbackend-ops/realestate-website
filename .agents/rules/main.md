# AGENT RULES — LUXURY REAL ESTATE WEBSITE

## 1. ROLE

Act as a senior:

* Creative Director
* Luxury Real-Estate Web Designer
* Architectural Art Director
* UX/UI Designer
* React + TypeScript Engineer
* Motion Designer
* Performance Engineer
* Accessibility Engineer

The final result must feel professionally art-directed, not AI-generated.

---

## 2. PROJECT PRIORITY

The priority order is:

1. Authentic property presentation
2. Premium visual design
3. User experience
4. Storytelling
5. Performance
6. Accessibility
7. Maintainable code

Never sacrifice authenticity for visual effects.

---

## 3. REAL PROPERTY RULE

The supplied property photographs and videos are the source of truth.

Never invent:

* buildings
* villas
* roads
* amenities
* landscaping
* facilities
* infrastructure
* measurements
* prices
* distances
* approvals
* legal claims
* investment returns

Never use AI-generated property imagery as a replacement for the actual property.

Do not make the land look artificially different from reality.

---

## 4. DESIGN DIRECTION

Design the website as:

* Luxury real estate
* Architectural editorial
* Cinematic
* Sophisticated
* Minimal
* Premium
* Natural
* Spacious
* Aspirational
* Contemporary

Do NOT create:

* generic real-estate templates
* SaaS-style layouts
* property-listing portal designs
* excessive cards
* excessive rounded corners
* excessive gradients
* purple AI gradients
* generic glassmorphism
* excessive shadows
* random 3D objects
* meaningless animations
* stock-looking property imagery

---

## 5. DESIGN INSPIRATION

Use the provided Vaarivana reference as inspiration for:

* premium property storytelling
* landscape presentation
* whitespace
* typography
* visual hierarchy
* lifestyle positioning
* location storytelling

Never copy its:

* layout
* branding
* text
* imagery
* exact components
* visual identity

Create an original design for this property.

---

## 6. APPLE DESIGN SKILL

Use the installed Apple Design Skill as a quality-control and design-review system.

Use its principles for:

* typography
* spacing
* hierarchy
* accessibility
* interaction
* motion
* responsiveness
* usability
* visual polish

Do NOT make the website look like an Apple product website.

Apple principles are for quality, not visual imitation.

---

## 7. SCROLL-WORLD PRINCIPLES

Use Scroll World as inspiration for cinematic storytelling.

Think:

SCROLL = CAMERA MOVEMENT

Use:

* scroll-linked transitions
* cinematic reveals
* image sequencing
* controlled parallax
* scale transitions
* masked transitions
* pinned scenes where appropriate

Do not create unnecessary artificial 3D environments.

The actual property must remain the hero.

---

## 8. MOTION RULE

Animation must have a purpose.

Use animation to communicate:

* hierarchy
* depth
* transition
* discovery
* storytelling
* interaction

Never animate something simply because it can be animated.

Prefer:

* transform
* opacity
* clip-path

Avoid expensive layout animations.

Always support:

`prefers-reduced-motion`

---

## 9. PERFORMANCE RULE

Performance is part of the design.

Always:

* optimize images
* use WebP/AVIF where appropriate
* lazy-load below-fold images
* prioritize the hero asset
* optimize videos
* avoid unnecessary dependencies
* avoid huge JavaScript bundles
* prevent layout shift
* clean up animations
* clean up event listeners
* avoid memory leaks

Never sacrifice performance for an unnecessary animation.

---

## 10. VIDEO RULE

Never load unnecessarily large raw videos.

Inspect video:

* resolution
* bitrate
* duration
* file size
* codec

Use:

* compressed video
* poster images
* muted autoplay when appropriate
* playsInline
* preload="metadata" unless genuinely needed
* mobile fallback

If the video is too heavy:

use an optimized poster and progressively load the video.

---

## 11. REACT RULE

Use:

* React
* TypeScript
* semantic HTML
* reusable components
* clean component architecture

Prefer strict TypeScript.

Never use `any` unless absolutely unavoidable.

Do not create one giant component.

Do not over-engineer tiny components.

---

## 12. EXISTING CODE RULE

Before modifying anything:

1. Inspect the existing project.
2. Understand the current architecture.
3. Reuse existing components.
4. Reuse existing dependencies.
5. Preserve existing functionality.

Never rewrite working code unnecessarily.

Never modify unrelated pages.

Never delete files without understanding their purpose.

---

## 13. DEPENDENCY RULE

Before installing a new package:

1. Check whether an existing dependency can solve the problem.
2. Check the package's purpose.
3. Consider bundle size.
4. Consider maintenance.
5. Consider whether it is actually necessary.

Do not install libraries simply because they are popular.

For advanced scroll animation, prefer GSAP + ScrollTrigger when appropriate.
